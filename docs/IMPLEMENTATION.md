# PIXL implementation and evidence plan

PIXL is an agent-operated pixel-art project language and an executable agent kit. The requested outcome authorizes local research, implementation, fixtures, and verification. Original source files remain authoritative evidence and are preserved byte-for-byte.

## Design decisions

| ID | Who | What | Where | Why / research | Proof |
|---|---|---|---|---|---|
| D01 | PIXL runtime | Typed graph, stable IDs, explicit dependencies | `pixl/graph.py`, `spec/PIXL-1.md` | Task context must retain relationships after compaction; [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) supports persistent notes and targeted retrieval, not any particular invented notation. | Resume from disk, dependency ordering, transitive impact tests. |
| D02 | PIXL compiler | Proprietary versioned wire grammar with UTF-8 byte-framed literals | `pixl/codec.py` | Unambiguous parsing and dense repeated structure; [Lost in the Middle](https://arxiv.org/abs/2307.03172) motivates testing retrieval rather than assuming long context suffices. Syntax choice is an engineering hypothesis, not a conclusion of that paper. | Canonical round trips, Unicode/delimiter cases, malformed-input rejection, equal-semantics size benchmark. |
| D03 | Agent and store | Compare-and-swap revisions, immutable snapshots, exclusive writer lock | `pixl/store.py` | Lost updates and stale evidence defeat persistent context. Python [`os.replace`](https://docs.python.org/3/library/os.html#os.replace) supplies same-filesystem atomic publication; it does not supply a distributed transaction. | Stale writer, parallel writer, rejected update and resume tests. |
| D04 | PIXL validator | Decisions require who/what/where/why, source references and executable proof evidence | `pixl/registry.json`, `pixl/graph.py` | Direct task requirement; observational claims and evidence remain distinct. | Missing evidence, wrong reference type, stale proof, false completion tests. |
| D05 | PIXL curator | Hash and section index the supplied corpus, deduplicate by bytes | `pixl/catalog.py`, `knowledge/` | Preserve source-specific meaning and avoid repeatedly loading 898 KB of embedded assets. Reference-first retrieval follows D01. | Stable section IDs, source ranges, duplicate detection, changed-source detection. |
| D06 | PixelLab adapter | Discover live schemas; prepare requests and journal real job identities | `pixl/platform.py` | [Official MCP docs](https://api.pixellab.ai/mcp/docs) describe asynchronous workflows and mode-specific parameters. A lost submission response is not evidence that no paid job exists. | Schema rejection, deterministic intent hash, unknown-outcome recovery, no automatic resubmission tests. |
| D07 | PIXL art specialist | Separate measurable file invariants from visual art judgment | `pixl/assets.py`, `pixl/poc.py` | Supplied art research and [Aseprite CLI](https://www.aseprite.org/docs/cli/) distinguish exported data from artistic quality. | Deterministic palette/alpha/dimension, tile adjacency, pivot, dither, light, cluster and material probes. |
| D08 | Harness adapter | External skill/plugin/MCP formats wrap the UDL | `plugins/pixl/`, `agent/` | [MCP tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools), installed Codex plugin contract, and [Claude plugin reference](https://code.claude.com/docs/en/plugins-reference) define host interoperability. They do not define PIXL's internal language. | Protocol subprocess and portable bundle tests; skill/plugin validators. |
| D09 | Evaluator | Publish reproducible measurements and unverified boundaries | `evidence/`, `scripts/verify.py` | Representation compression, grammar correctness, art quality and LLM reasoning are different outcomes. | Equal-content comparisons and independent agent exercise; no universal superiority claim. |
| D10 | Knowledge compiler | Compile curated methods, applicability atoms and actual POC receipts into PIXL | `scripts/build_knowledge.py`, `knowledge/library.px` | Source conditions and failure behavior must survive the transition into operational context. This is an engineering choice following D01/D05; original source ranges remain authoritative. | Lossless prerequisite/procedure/check/pitfall/applicability tests; closed one-method retrieval; current source/receipt hashes. |

## Architecture choice

Three approaches were evaluated: a prompt-only shorthand (cannot enforce referential integrity or detect stale writes), an opaque binary graph (requires a decoder for every model interaction and hides useful structure from the model), and a compact typed wire grammar backed by deterministic tools. PIXL uses the third. Human readability has zero weight in the wire-design criteria. Parse reliability, contextual closure, semantic density, measured tokenizer cost, and executable validation determine the design.

Text literals carry source excerpts, descriptions accepted by PixelLab, and semantic knowledge that the model must reason about. These are payload, not an attempt to turn a language model into a new trained architecture. No evidence establishes that all existing text representations are intrinsically bad for agents. PIXL does not make that claim.

## Implementation sequence

1. **Language and graph.** Who: runtime implementer. What: grammar, registry, semantic rules, context/impact/ready commands. Where: `pixl/`, `spec/`, `tests/test_language.py`, `tests/test_graph.py`. Why: D01/D02/D04. First exercise malformed input and missing dependencies; then implement and run round-trip and graph tests.
2. **Durability and source grounding.** Who: persistence implementer. What: revision-checked store and source catalog. Where: `pixl/store.py`, `pixl/catalog.py`, `tests/test_store.py`. Why: D03/D05. Exercise stale writer and source mutation before implementing publication.
3. **PixelLab and artwork.** Who: platform/art implementer plus source curators. What: discovery-driven request preparation, local job state machine, image inspections and concrete method POCs. Where: `pixl/platform.py`, `pixl/assets.py`, `pixl/poc.py`, `knowledge/`. Why: D06/D07. Tests use real local artifacts and explicit simulated service outcomes; no live service execution is claimed.
4. **Agent integration.** Who: kit adapter implementer. What: portable Claude/Codex profiles, skill and local MCP bridge. Where: `agent/`, `plugins/pixl/`, `pixl/mcp.py`. Why: D08. Verify actual subprocess requests, bundle portability and host manifest validators.
5. **End-to-end verification.** Who: evaluator. What: initialize, validate, focus, mutate, detect drift, re-ground and resume; reproduce POCs and measure density. Where: `scripts/verify.py`, `scripts/benchmark.py`, `evidence/`. Why: D09. Record failures separately from final results. Live PixelLab generation and controlled multi-model reasoning comparisons remain explicitly unverified unless actually run.

All units include their own tests; global constraints are Python 3.11+, UTF-8, no service secrets in project state, no implicit remote mutation, no modification of supplied source files, and no unsupported inference of artistic success from mechanical checks. JSON at CLI/MCP boundaries and research catalogs is host interchange; `.px` is the operational UDL. `knowledge/library.px` compiles source conditions and actual POC receipts into that UDL; its build refuses a report whose runner or knowledge hash is stale. Work is performed in this checkout so the supplied untracked sources remain available.
