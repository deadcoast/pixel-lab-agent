# Packaged PIXL host evaluation

The next operation is a recorded evaluation of the packaged production profile in
Claude Code and Codex. The evaluator remains a development collaborator. The
eleven cases in `evaluations/profile-scenarios.json` are the behavioral authority;
their expected answers are never supplied to the model under test.

| WHO | WHAT | WHERE | WHY |
| --- | --- | --- | --- |
| Maintainer | Freeze package, fixture and prompt identities before a trial | `evaluations/`, `evidence/host-evaluation/` | A dirty source revision alone cannot identify the instructions actually tested. |
| Native host | Discover and invoke the packaged skill, then use real local tools | Fresh project outside the source checkout | Scripted runtime exercises cannot establish model instruction following. |
| Evaluator | Review every applicable criterion against transcript events and retained files | Per-run review records | Process exit, reassuring prose and fixture acceptance are different observations. |
| Production reviewer | Assess actual supplied pixels and destination behavior when available | Controlled local images; later authorized real production | A successful host trial does not establish PixelLab generation or game readiness. |

## Trial contract

Use a copied, hash-verified `plugins/pixl` bundle and the selected uv-managed Python
environment. Record the launcher/configuration, host version, requested and observed
model when available, profile and skill hashes, runtime file hashes, Git revision
and dirty source identities, prompt, input files, stdout/stderr, tool observations,
output hashes, process outcome and limitations. Preserve every attempt, including
authentication errors, permission failures, interruptions and failed criteria.

Do not modify global host configuration or copy credentials. Codex supports
session configuration overrides; its native app-server skill discovery/input
protocol is documented in [official skills guidance](https://learn.chatgpt.com/docs/app-server#skills).
Claude's installed CLI documents session `--plugin-dir`, `--strict-mcp-config`,
`--setting-sources` and structured print output. Verify discovery with the actual
installed versions before counting behavior. Authentication is a host prerequisite,
not a PIXL criterion. Keep blocked host/case rows unverified.

Start with role routing, incomplete intake, project-specific alpha treatment,
missing provider and visible rejection pressure. Use deterministic local image
fixtures with an evaluator-only oracle; mark these as controlled fixtures, not
commissioned art or PixelLab output. Repeat selected identical tasks in fresh
sessions. Exercise a cold continuation if a trial writes meaningful state, with
only persisted project files and a new user message. Never include earlier model
transcripts or the rubric in the cold session.

Only local PIXL MCP is configured. No paid image generation, invented remote
observations, or engine acceptance is part of this first matrix. The existing
provider/family fixtures may test state handling but their synthetic acceptance
claims cannot become real artistic or engine outcomes. Record partial coverage
instead of claiming all eleven scenarios were executed.

## Reporting and stopping condition

Keep three independent layers: host discovery/execution, observed profile behavior,
and actual production outcomes. Report both successful and unsuccessful criteria;
do not infer reliability or causal model superiority from a small unmatched sample.
The deliverable is a reproducible runner, retained trials, criterion reviews, and
the next concrete tasks derived from the observations. If a host cannot authenticate,
complete the runnable half and its replay instructions, retain the blocker, and
leave cross-host comparison explicitly incomplete.

No runtime semantics or production instructions change merely to improve a score.
Any later correction needs a demonstrated failure and fresh attempts against the
changed instruction identity. Existing source, provider and family receipts remain
historical evidence and are not regenerated by this evaluation.
