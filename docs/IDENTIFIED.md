## Source-code strengths to preserve

- **A clear specialist identity.** The profile explicitly combines pixel-art expertise, caller authority, official tools and project-specific purpose. Development/production role boundaries are documented in [AGENTS.md](../AGENTS.md).
- **A common operation layer.** [Service dispatch](../pixl/service.py), CLI and local MCP expose shared runtime operations. The specialist can use the host's other tools rather than being confined to an isolated image endpoint.
- **Versioned saved-state semantics.** [PIXL/1](../spec/PIXL-1.md) and [PIXL/2](../spec/PIXL-2.md) have registries and deterministic encoding. They support explicit history and validation instead of relying on conversation memory alone.
- **Publication checks and immutable history.** [Store operations](../pixl/store.py) use locks, compare-and-swap expectations, atomic replacement and transition validation. History is retained; recovery is explicit.
- **Durable provider intent.** [Jobs](../pixl/jobs.py) distinguish prepared, submitted, unknown and terminal observations. An uncertain remote outcome is not treated as authorization to submit again.
- **Connected allocation and production.** [PLAR preparation](../pixl/plar_prepare.py) and [production plans](../pixl/production_plan.py) recover interrupted links, preserve previous generations and reject stale selection/pending-work replacement.
- **Literal criteria survive handoff.** [Production review](../pixl/production_review.py) binds comparisons to exact inputs while explicitly reporting that semantic judgment is not automatically assessed. Keep that separation.
- **Focused authoring is already implemented.** [Authoring context](../pixl/authoring_context.py) exposes selected tasks, prerequisites, literal requirements and source locators without inheriting an old acceptance verdict.
- **Mechanical and artistic evidence remain distinct.** Inspection views and explicit judgments support real review without declaring aesthetic success from image dimensions or a passing schema.
- **Delivery has real artifact identity.** [Handoff](../pixl/handoff.py) checks current requirements/state and stores immutable caller results. Current successor delivery is backed by actual package and destination evidence.
- **The optional HTTP boundary is deliberately narrow.** [PixelLab HTTP adapter](../pixl/pixellab_http.py) limits destinations, response sizes and retries and separates simulated transport. The host's official MCP route supports the wider operation set.
- **Packaging and evidence are unusually inspectable.** Minimal runtime dependencies, copied-plugin/wheel checks, source documents, failed trials and exact receipts make later investigation possible. Do not delete this infrastructure to make onboarding shorter.

## Source-code weaknesses and operational consequences

- **Routine review still drops into internal record construction.** The successor acceptance needed a maintainer script for evidence/verdict records; a reversed record constructor was rejected, and prior nomination repair was separate. The necessary mechanisms exist, but their normal interface is incomplete.
- **Native qualification trails local capabilities.** A generic Codex child called PIXL is not evidence of named-role loading. Within-cycle [Claude recovery and continuation](../evidence/native-continuation/README.md) and one [explicitly registered Codex role with completed recovery/handoff](../evidence/named-codex-role/README.md) now have scoped passes. Saved-file restart, within-process follow-up and separate-process continuation retain their distinct evidence; automatic discovery and broader reliability remain open.
- **Entry-point claims have drifted.** [README](../README.md) still describes 34 MCP tools and says live generation/target import were not run. Current source exposes 36 tools, and retained production evidence says otherwise. Historical reports should remain historical; current-facing claims need reconciliation.
- **Cross-module private helpers carry public behavior.** For example, production review imports private plan/PLAR helpers, and authoring context uses private job/PLAR helpers. This makes seemingly local changes affect other public operations.
- **Large dynamically shaped operation bodies increase maintenance risk.** The measured largest modules include `poc.py` (1,616 lines), `platform.py` (1,220), `inspection_views.py` (912), `inspection.py` (877), `plar_prepare.py` (725), `jobs.py` (704) and `production_plan.py` (691). Size alone is not a bug; extraction should follow specific operation boundaries and regressions.
- **Authoring-context selection is not fully narrow.** It includes every project `P.in` choice. Relevant source closure is valuable, but unrelated project choices can expand a selected task's context; measure and filter with authority-preservation checks.
- **Large report transport has caused a concrete host failure.** Focused-authoring evidence records Windows command-length failure while saving a large MCP result. File-oriented output and concise result summaries would remove this avoidable step.
- **Hashes and path domains are easy to confuse.** Canonical state, raw file, requirements and manifest hashes serve different purposes. CLI paths and MCP root-relative paths also differ. Errors and examples should make the expected domain explicit.
- **Snapshot and current acceptance have different meanings.** A retained delivery manifest can describe its initial unaccepted snapshot while later state records acceptance. Both are correct; a caller needs the current result and its chronology without silently rewriting history.
- **Interface definitions have several maintenance points.** CLI arguments, MCP declarations and service routing need parity checks. This is a maintenance risk, not a claim that every current route is inconsistent.
- **Broad quality claims exceed the outcome sample.** Queue UI assets have real evidence; directional characters, tiles, other engines and independently repeated artistic decisions do not inherit that result.
- **Performance and portability need measurements.** Context assembly scans records and hashes selected files; publication validates related state; current evidence is Windows-heavy. No measured performance regression or universal OS failure is asserted here.
