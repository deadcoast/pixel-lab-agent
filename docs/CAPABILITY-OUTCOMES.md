# Capability and outcome matrix

Use this matrix to choose a useful PIXL assignment and the route that already supports it. Start with the task below, follow its linked guide in the consumer project, and apply that project's brief and acceptance criteria. Existing authorization carries forward; a gap in qualification is work to develop and check, not a request to stop for human approval.

Reviewed **2026-11-12**, active cycle `IDENTIFY-2026-11-09-01`, initial finding **NF-04**, now updated with bounded **CF-08/TM-03** recovery outcomes and retained native-conformance limits. This is a development qualification map of retained and explicitly linked new evidence, not a guarantee for every project. **M1/M2 and broader M3/M4 remain open.** [Current development work](../TODO.md) and the [NF-04 review](../evidence/capability-outcomes/README.md) record the next increment.

- **Documented (D):** intended behavior or operation guidance exists; no task outcome is implied.
- **Locally checked (L):** deterministic code, fixture or installation checks support the stated mechanism.
- **Natively exercised (N):** a recorded host actually used the route; partial/failing runs stay partial/failing.
- **Outcome-reviewed (O):** the stated task result was inspected against its contract. The row says whether this involved reused art, real provider output, a renderer and a caller. One bounded review is not broad reliability.

These labels describe different evidence, not a score or a ladder that turns local checks into artistic expertise. **Human acceptance: not recorded by this matrix, assessed separately.** Development-assistant and native-agent judgments are labeled as such; no human sign-off is needed to complete NF-04 or proceed with authorized development.
