def setup(project, destination, python, resume):
    if resume:
        raise ValueError("Authoring begins from the frozen consumer, not a prior trial")
    root = Path(__file__).resolve().parents[1]
    source = root / "evidence/pixellab-family-production/20261108/project"
    excluded = (".agents", ".codex", "__pycache__", "AGENTS.md", "SESSION.md")
    shutil.copytree(
        source, project, dirs_exist_ok=True, ignore=shutil.ignore_patterns(*excluded)
    )
    original = json.loads((project / "plar.txt").read_text(encoding="utf-8"))
    branch = copy.deepcopy(original)
    # The original allocation and accepted production stay byte-identical.
    # This separate requirements index is a prospective authoring branch, not a reset.
    for asset in branch["assets"]:
        asset.pop("production", None)
        if asset["id"] in ("queue.working", "queue.retry", "queue.paused"):
            asset["status"] = "todo"
            asset["next"] = (
                "Author the prospective production graph; accepted original delivery is preserved separately."
            )
    write_json(project / "authoring-plar.txt", branch)
    shutil.copyfile(
        root / "evidence/native-authoring/20261109/official-discovery.json",
        project / "official-discovery.json",
    )
    shutil.copyfile(Path(__file__), destination / "plar_authoring_case.py.txt")
    shutil.copyfile(
        root / "evaluations/authoring_mcp.py", destination / "authoring_mcp.py"
    )
    write_json(
        destination / "origin.json",
        {
            "source": str(source),
            "files": inventory(source, excluded),
            "branch_path": "authoring-plar.txt",
            "branch_change": "Separate copy with production links removed and three stage statuses planned; semantic requirements and original files preserved.",
        },
    )
    (project / "AUTHORING-STAGE.md").write_text(
        """# Author the queue-family workflow through the new interface

The accepted original queue family is retained. Replace the prior manual wiring
with a new prospective plan in this isolated authoring branch. This assignment is
about authoring and recoverability, not regenerating the accepted assets.

Use authoring-plar.txt for new Working, Retry and Paused selections. Preserve the
original plar.txt and every existing record/file. Read the actual source consumers,
scoped style decision and production findings. Existing Ready and the accepted
Working seed are available inputs, with their actual provenance and prior reviews.
Use the established contracts/adoption/destination choices when applicable. Do
not turn the reference's measured colors, alpha or cluster count into new owner
requirements. Preserve the qualitative cool-blue accent, state distinctions,
transparency, actual frame slicing/timing and both consumer responsibilities.

Author a connected plan for Working, Retry and Paused plus collective delivery
including Ready. Bind each final output to its current authoring-plar selection.
Working's stage must depend on the existing accepted seed output, not an invented
future candidate. Preserve member-specific checks and collective continuity,
non-color distinction and destination review. Existing Start remains unchanged.
Use production-plan / stage-prepare through local MCP; do not hand-build the
equivalent T/F graph to bypass the new interface. The schema/reference is in the
installed kit. The installed kit is authoritative; old CURRENT-HANDOFF points to
the earlier production kit and describes that already-completed assignment.

Choose and prepare Working's next executable official PixelLab operation from
the retained seed and current declarations in official-discovery.json. Use the
host's pixel-art knowledge and the prior failed/successful approaches to justify
your choice. Include actual input image bytes via a supported data/base64 input
when practical; an old upload handle or local filename is not fresh transport.
If the provider result needs assembly to the four-frame destination, retain the
exact intended frame-selection/assembly policy and its separate review obligations.
Do not label preparation, schema validity or a prior review as new output acceptance.

The evaluation server will fail one allocation write after saving your plan;
recover the same operation without duplicate records or changing its meaning.
After the first successfully prepared request it will supply a scoped caller
requirement update. Read and reconcile that observation, preserve the original
plan/request, and report what can and cannot proceed. No revised generation is
assigned in this continuation. Local readiness/dispatch checks may establish that
the old request is blocked; do not call a remote generation tool.

The parent caller owns the independent comparison and AUTHORING-RESULT.json.
Return exact project-relative paths/hashes, generated task/output/job IDs, original
and current requirement identities, observed recovery, remaining checks and next
action. Keep preparing this branch separate from the already-accepted original
package. Do not end with only a specialist self-audit or a running background child.
""",
        encoding="utf-8",
    )
    return None


def local_server(project, destination, python, package):
    return {
        "command": str(python),
        "args": [
            str(destination / "authoring_mcp.py"),
            "--root",
            str(project),
            "--kit",
            str(package),
            "--events",
            str(destination / "evaluation-events.jsonl"),
        ],
    }
