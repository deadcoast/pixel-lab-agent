status and applicable scope; inspection links to that procedure. The main skill

skipped the linked procedure in the first revision. Requested aesthetics must

Both ask for `APPROACH.md` and a useful final response only. They prohibit production
art, provider calls and PX2 state changes. Diagnostic images and measurements can
support planning; this scope does not test full intake publication or art production.

## Evidence and reproducibility

- `responses/` extracts each actual final response and the entire saved approach,
  with source locators and hashes. These extracts leave behavior ungraded.
- `review.md` identifies failures across the whole approach and separates them
  from useful local work. Earlier failed versions remain failed.
- `input-measurements/` records exact fixture hashes and observations. The drone
  has 88 visible pixels and three components; this is a counterexample fixture,
  not evidence for a universal topology rule or artistic acceptance.
- `earlier-failures/` preserves exact selected historical files and their source
  paths/hashes. They are not receipts for the current skill.
- `event-index-v2/` indexes observable image/read calls. The earlier index omitted
  Codex custom-tool events and remains preserved; neither index proves that a call
  succeeded without its corresponding native result.
- `verification/` retains full repository check commands and output by run.
- `native-observations/` locates actual image payloads and Claude's injected skill
  text in the native records. Delivery to a host context does not establish
  physical display scale, perception, compliance or art acceptance.
- `approach-events/` retains saved-approach calls and their actual results for the
  last two revisions. Writes and reads are distinguished in manual review; merely
  mentioning `APPROACH.md` does not establish a complete read or successful audit.
- `readback-evidence/` checks complete text delivery against the known draft or final
  file and retains those readback texts. This mechanical comparison does not verify
  the model's understanding or the correctness of its audit conclusion.

Native records retain exact package identities, inputs, streams, journals and
outputs. A full verifier between instruction revisions regenerated four bundled
proof/example resources. Their hashes differ, so this is not a claim that every
package byte except the guidance stayed identical. Runtime/profile bytes, fixture
bytes, briefs, host controls and the time limit remain matched. Final repository
verification also regenerates proof resources; frozen trial packages retain their
original bytes.

`archives/` contains seven verified ZIP archives with 1,172 files and per-file
SHA-256 manifests. All 26 attempts, frozen packages, exact wrappers and the unchanged
shared recorder are retained. Expanded copies remain locally available and ignored
by Git; extract an archive into this directory to restore its original series path.
`final-checks/result.json` verifies all 86 checked source hashes, all 101 bundle
entries, final trial instruction/runtime/profile identity, matching protocol fields
and the separately declared time allowances. The previous handoff section is
verified unchanged. These are identity checks, not behavioral approval.

The first-revision Claude style trial and the 360-second final-revision Claude drone
trial wrote diagnostic images under system temporary directories outside their
assigned projects. Native records retain the image payloads, but these attempts
do not prove all writes stayed within the requested project boundary.

## Remaining limits

scenarios. It does not establish model reliability, successful live PixelLab
generation, representative-sample acceptance, artistic quality, animation/tile
continuity or engine import. Native-scale viewing coverage varies and remains
distinct from planning success.

updates; PX-EVAL-003 still contains unattempted outcome/recovery cases. Completed
Claude intake handoff behavior from PX-SKILL-001 remains unverified. Open paces
therefore remain, and the user's all-paces-complete PACER condition is false.
