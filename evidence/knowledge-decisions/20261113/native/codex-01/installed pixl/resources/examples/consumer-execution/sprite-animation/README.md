# Sprite animation consumer (`sprite-animation-v1`)

This reusable browser consumer reads an actual animation module and exact package
PNGs. It supports full-frame images and atlas crops, authored unequal durations,
looping and one-shot clips, per-frame pivots, and native/integer zoom. The interface
provides clip selection, play/pause, frame stepping, scale and an optional anchor
crosshair. No artwork is generated by this renderer.

Use the public `consumer-execute` / `pixl_consumer_execute` operation to bind an exact candidate context,
explicit destination map and this renderer profile. The operation retains its
config, installed six-file renderer, browser evidence, independent check, NF-06
observation and import result. See the [parent guide](../README.md) for that flow.

## Authored contract

The module configured as `modules.animation` exports `animation` and
`frameAt(clipId, elapsedMs)`. For example:

```ts
export const animation = {
  viewport: [40, 36], background: '#172336', sampling: 'nearest',
  clips: [{
    id: 'walk', label: 'Walk cycle', loop: true, anchor: [20, 28],
    frames: [
      { id: 'plant', path: 'assets/motion/plant.png',
        rect: [0, 0, 16, 16], duration_ms: 120, pivot: [8, 14] },
      { id: 'pass', path: 'assets/motion/pass.png',
        rect: [0, 0, 16, 16], duration_ms: 180, pivot: [8, 14] }
    ]
  }]
};
export function frameAt(clipId, elapsedMs) {
  const clip = animation.clips.find(value => value.id === clipId);
  if (!clip) throw new Error('Unknown clip');
  const duration = clip.frames.reduce((sum, frame) => sum + frame.duration_ms, 0);
  let at = clip.loop ? Math.max(elapsedMs, 0) % duration
                    : Math.min(Math.max(elapsedMs, 0), duration);
  for (let index = 0; index < clip.frames.length; index++) {
    if (at < clip.frames[index].duration_ms) return index;
    at -= clip.frames[index].duration_ms;
  }
  return clip.frames.length - 1;
}
```

These example dimensions, frame durations and pivots are consumer decisions,
not universal animation requirements. Each frame's crop is painted with its
pivot at the clip's anchor. Source crops must fit their PNG. Every explicit
mapped destination must be used by a frame. Different clips may reuse files.

The bounded profile accepts 1–4 clips, each with 2–16 frames, a logical viewport
up to 128×128, and 1–4 distinct integer scales from 1 to 16. Clip IDs use letters,
digits, dot, dash or underscore and at most 64 characters. Frame IDs are unique
within a clip. Paths are canonical `assets/...png` paths. Anchors are integer
pairs from 0 to 128; pivots are integer pairs from -128 to 128. Durations are
positive integer milliseconds up to 60,000. Durations too short for the actual
browser cadence, or clips too long for the observation timeout, remain failed
or unavailable observations rather than receiving synthetic timing evidence.

The configuration is an exact version-1 object:

```json
{
  "version": 1,
  "profile": "sprite-animation-v1",
  "modules": {"animation": "src/animation.ts"},
  "destinations": {"motion.plant": "assets/motion/plant.png", "motion.pass": "assets/motion/pass.png"},
  "scales": [1, 3],
  "observed_wraps": 2,
  "phase_timeout_ms": 10000,
  "timeout_seconds": 90
}
```

## Local inspection and diagnosis

For an interactive preview, run:

```text
node renderer/server.mjs --project CONSUMER_ROOT --config CONSUMER_ROOT/config.json
```

Open the printed loopback URL. The server exposes only the renderer UI, the
configured source tree and mapped assets. Stop the process when finished.
`src/` TypeScript must be supported by Node's type stripping; module imports
must refer to actual files. This runs trusted consumer code and is not an OS
sandbox.

For direct retained diagnostics with an installed Chromium browser:

```text
node renderer/capture.mjs --project CONSUMER_ROOT --config CONSUMER_ROOT/config.json --out CONSUMER_ROOT/fresh-capture
python renderer/check.py --project CONSUMER_ROOT --capture CONSUMER_ROOT/fresh-capture --out CONSUMER_ROOT/fresh-check.json
```

Use the selected environment's Python. `--browser PATH` can select an installed
browser. Capture requires a fresh output directory and owns only its new browser
process, loopback server and temporary browser profile; it retains cleanup facts
and does not close a user's existing browser.

`capture.json` separates `views` (controlled frame steps, each with canvas and
screen PNGs) from `playbacks` (actual RAF ticks, transition PNGs, frame indexes,
elapsed times, wraps and skips). Canvas references use `image: {path, sha256}`.
The checker independently reconstructs crop, alpha composition, pivot placement,
nearest scaling and unequal-duration frame selection; it checks every source
hash, served destination, retained image and screenshot crop. For a loop it
requires every frame and the requested wrap count without skipped transitions;
for a one-shot it requires every frame and the final frame through the authored
terminal time. A screenshot or controlled step cannot substitute for playback.

`observation.py --project ... --capture ... --context ... --renderer ...
--destinations ... --out ...` converts these retained observations to NF-06.
Motion samples reference actual PNGs. `frame_ms` is null because authored frame
durations may differ. Complete ticks and authored durations stay in the attached
raw evidence. The bridge does not execute another browser or grant acceptance.

Correct rendering and timing do not establish good gait, contact, weight,
readable poses, identity preservation, artistic quality, or another target
engine's behavior. Those require domain review and remain separate from human
acceptance. Synthetic test pixels live only in the test helper and are labeled
as tooling diagnostics.
